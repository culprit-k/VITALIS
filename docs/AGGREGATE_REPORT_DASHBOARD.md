# Aggregate research dashboard

The Streamlit dashboard supports three aggregate-only result formats:

1. Baseline reports containing `test_metrics` and `patient_counts`.
2. Full cross-cohort horizon reports containing `aggregate_by_horizon`.
3. Source-verified aggregate summaries containing `aggregate_metrics`.

## Run locally

Install the optional dashboard dependency and the project:

```bash
pip install -e ".[dashboard]"
streamlit run dashboard/app.py
```

Upload only aggregate JSON files generated by the VITALIS scripts. The dashboard rejects unsupported schemas, non-finite metric values, and known row-level fields such as patient identifiers and prediction arrays. It also enforces a 10 MiB upload limit. This is a defensive UI check, not a data-loss-prevention system or authorization to upload sensitive data.

For the synthetic adaptive-twin demo, use `streamlit run dashboard/twin_demo.py`. That sandbox generates synthetic signals and is separate from the retrospective prediction experiments.

## Interpretation and privacy boundaries

- Do not upload raw cohort data, row-level records, patient identifiers, prediction vectors, or score archives.
- Keep raw PhysioNet files, caches, and individual predictions outside Git and outside the dashboard.
- Horizon metrics concern entry into the Challenge 2019 positive-label window; they are not independently adjudicated biological onset predictions.
- Set B is a benchmark evaluation cohort, not prospective or independent clinical validation.
- The UI does not train models, select thresholds, or recommend patient-care actions.

VITALIS remains a research prototype and must not be used to guide diagnosis, triage, treatment, or patient care.
