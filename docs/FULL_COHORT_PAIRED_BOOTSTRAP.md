# Full-cohort paired patient-cluster bootstrap — 200 replicates

## Results

Each interval is a paired, patient-cluster percentile bootstrap of the temporal-minus-static metric difference within that seed's held-out test split. Patients are sampled with replacement; all hourly rows belonging to a sampled patient receive the corresponding multiplicity weight.

| Split seed | Metric | Mean bootstrap difference | 95% percentile interval |
|---:|---|---:|---:|
| 42 | AUROC | +0.0253 | +0.0149 to +0.0359 |
| 42 | AUPRC | +0.0071 | +0.0024 to +0.0151 |
| 42 | Brier score | −0.0088 | −0.0103 to −0.0069 |
| 123 | AUROC | +0.0268 | +0.0169 to +0.0369 |
| 123 | AUPRC | +0.0013 | −0.0036 to +0.0070 |
| 123 | Brier score | −0.0066 | −0.0086 to −0.0048 |
| 2026 | AUROC | +0.0253 | +0.0140 to +0.0368 |
| 2026 | AUPRC | +0.0043 | +0.0004 to +0.0088 |
| 2026 | Brier score | −0.0080 | −0.0099 to −0.0059 |

All three seeds completed 200 valid replicates each. The positive AUROC difference and negative Brier difference are consistent across seeds. AUPRC is less consistent: its interval crosses zero for seed 123.

## Interpretation and limits

These are conditional uncertainty intervals for retrospective hourly challenge-label metrics, not external validation. The 0.5 threshold was not clinically selected. Hourly label performance does not establish patient-level event sensitivity, lead time, or clinical false-alarm rates. No clinical-use claim is justified.

**Reproducibility caveat:** the local working copy used for this execution was reconstructed from checked-in evaluator logic and is not byte-identical to the GitHub blob. The checked-in evaluator now includes the intended patient-cluster bootstrap implementation, but strict byte-identity of this run remains unverified.

Dataset integrity totals: 20,336 patients, 790,215 rows, 17,136 positive hourly challenge labels. No raw patient data, patient identifiers, or row-level predictions are included.

## Higher-replicate follow-up: seed 42 (1,000 replicates)

To avoid repeatedly fitting models for every bootstrap replicate, I saved the held-out score vectors locally (not in Git) and ran a batched patient-cluster bootstrap. This completed 1,000 valid replicates in approximately 28 seconds after the score vectors were available. The earlier 200-replicate estimates for seed 42 remain shown above for comparison.

| Metric | Mean bootstrap difference | 95% percentile interval |
|---|---:|---:|
| AUROC | +0.0250 | +0.0150 to +0.0351 |
| AUPRC | +0.0070 | +0.0022 to +0.0154 |
| Brier score | −0.0089 | −0.0108 to −0.0071 |

Machine-readable seed-42 1,000-replicate artifact: [aggregate JSON](../results/full_cohort_paired_patient_cluster_bootstrap_seed42_1000_2026-10-14.json).

The estimates are close to the earlier 200-replicate interval for seed 42, as expected. **This does not close source reproducibility:** the held-out scores were generated with a reconstructed local evaluator, not a byte-identical repository checkout. The batched bootstrap metric calculation was spot-checked against the checked-in weighted-metric implementation on tied-score test cases. Seeds 123 and 2026 remain at 200 replicates each; they have not yet been upgraded to 1,000.


## Reusable runner and CI

A checked-in bootstrap-only runner is now available at [scripts/bootstrap_heldout_scores.py](../scripts/bootstrap_heldout_scores.py). It reads a local-only NPZ score archive and exports aggregate JSON without patient-level scores or group labels. The randomized metric-parity and aggregate-only tests passed in [GitHub Actions](https://github.com/culprit-k/VITALIS/actions/runs/38563811238); the runner commit's CI also passed [here](https://github.com/culprit-k/VITALIS/actions/runs/38563789399).

Example after preparing a local score archive (never commit the archive):

```bash
python scripts/bootstrap_heldout_scores.py \
  --scores /secure/local/path/heldout_scores_seed42.npz \
  --seed 42 --replicates 1000 --batch-size 8 \
  --output /secure/local/path/bootstrap_seed42_1000.json
```

The script's correctness tests passed; the saved seed-42 aggregate artifact above was generated by a separate local implementation of the same batched method, not by executing this exact checked-in source file. Source-identical end-to-end reproduction remains open.


## Final higher-replicate follow-up: all three seeds at 1,000 replicates

After running score preparation separately for each split seed, the batched bootstrap completed 1,000 valid replicates for seeds 42, 123, and 2026. Bootstrap-only runtime was approximately 27–28 seconds per seed once held-out scores were available.

| 123 | AUROC | +0.0264 | +0.0169 to +0.0368 |

Aggregate-only machine-readable artifact: [1,000 replicates × 3 seeds](../results/full_cohort_paired_patient_cluster_bootstrap_1000x3_2026-10-14.json).

The AUROC intervals remain above zero and Brier intervals below zero for each split. AUPRC intervals cross zero for seeds 123 and 2026, so the precision-recall improvement is not consistent enough to claim a robust gain. These are conditional split-specific intervals, not independent external validations.

**Reproducibility limitation remains:** held-out score vectors were generated by a reconstructed local model-evaluation script, not a byte-identical checkout of the repository source. The new checked-in bootstrap-only runner is tested in CI, but that does not retroactively make the score-generation source identical. Raw patient data and held-out score vectors remain outside Git.
